## 四、恢复指引

### 4.1 回到 Lua 版开发

```bash
git checkout archive/urhox-lua-2026-10-11     # 检出封存点
# 或
git checkout -b revive-lua archive/urhox-lua-2026-10-11
```

解冻：删掉本文件顶部的冻结声明，并在 `AGENTS.md` 恢复对 `scripts/` 的写入授权。

### 4.2 取回规则真源供 H5 使用

**不要拷贝 `prot/*.js`** —— 保持单一真源，H5 侧用 Vite alias 指过去：

```ts
// h5/vite.config.ts
resolve: {
  alias: {
    '@engine': path.resolve(__dirname, '../prot/engine.js'),
    '@data':   path.resolve(__dirname, '../prot/lua-data'),
  }
}
```

这样 `prot/` 的测试继续守护同一份规则代码。

**数据管线**：`prot/lua-data/*.json` 直接 import，构建期跑 `p1-verify.js` 做校验门禁。

### 4.3 已验证的视觉规则（P3 复刻时照搬）

Lua 版真机趟过的坑，H5 复刻时直接复用结论，**不必重踩**：

| 规则 | 说明 |
|---|---|
| **立绘底部锚定** | 立绘按底边对齐，不随容器高度居中 |
| **贴图比例** | 卡片宽高按立绘 512:768 反推，勿用自适应宽（Yoga 下会塌成细条） |
| **Card 边框 `flex` 定宽** | 自适应宽 + wrap 文本在 Yoga 下塌成 21px 细条，必须 `flex` 定宽 |
| **容器重建须 `Destroy`** | `ClearChildren` 只 detach 不释放（Yoga 节点无 `__gc` 兜底）→ 长会话内存单调增长 |
| **跨重建复用的控件先 `Remove`** | 罗盘等常驻控件须先摘除再销毁，避免连坐销毁 |
| **`clearMain` 先 cancel 再 clear** | 渐显队列会回填内容，顺序颠倒会残留上一页文本 |
| **JS 的 `and nil or` 陷阱** | Lua 中 `x and nil or y` 恒等于 `y`，禁用态须显式分支 |
| **全角括号不能用字符类** | Lua 模式按字节匹配，`[^（）]` 会误排除常见中文字节（`，`=EF BC 8C） |
| **枚举遍历用 `pairs` 无序** | `pairs` 是哈希序，展示序须显式声明（结算面板曾因此随机跳序） |
| **Windows CRLF** | 注释剥离正则 `/--.*$/` 不匹配 `\r`，切行须用 `/\r?\n/` |

### 4.4 已知盲区（差分测试抓不到）

对拍网能证明「JS 与 Lua 一致」，**不能证明「两侧都对」**。本项目已实证出现过两侧同错的语义缺陷：

> **抉择卡重复结算**：`choiceUsed` 只过滤强制发牌候选 `crest`，未从普通抽牌池 `pool` 剔除，导致已落定的「一次性」卡被再次发出并二次结算。JS 与 Lua 完全同错，故 100/100 全绿仍放行。2026-10-11 由独立审查发现并修复（`f0495d9`）。

**建议**：H5 阶段为关键规则补充**不依赖 JS 的独立断言**（例如「抉择卡落定后 N 轮内不得再出现于 offer」）。
