## 这个游戏是什么

多剧本历史偏移模拟器。玩家扮演一位历史人物（首发五位：李斯、荆轲、韩信、项羽、陈胜），从他人生的第一个岔路口开始，每次选择都在与「历史的惯性」对抗。

**核心机制三条：**

1. **偏离度**（0–100，只增不减）——玩家与史实的累计分歧。分四段位：循史 0–20 / 微澜 21–45 / 改流 46–70 / 逆天 71–100。段位越高，世界修正反噬越强。

2. **行动卡回合制**——每回合发 4 张卡：关键事件卡 ×1（限时 3 回合，倒计时只随打出行动卡递减）+ 普通行动卡 ×3（每章池 12 张，同轮不重复）。同一行动同章重复使用时收益递减、代价不减。

3. **险招**——选项的门槛是软门槛：不达标不是禁用，而是可以掷骰冒险。六档成功率按未达标差值取最低（gap≤3→70% / ≤6→50% / ≤9→40% / ≤12→30% / ≤15→20% / >15→15%）。带「史」标记的选项升一档，封顶 70%。失败则该选项在本次事件内烧毁。

终局四维评分（功业 / 存续 / 史评 / 影响）合成总分，再乘难度、逆天、回溯三个系数，得 S/A/B/C/D 评级。结局附一段仿《史记》史官断语体的史传，可导出分享卡。

**浏览器**：起一个静态服务器指向原型根目录，打开 `index.html` 即可。零依赖，不需要构建。

node server.js --port 7100

## 移植时值得注意的几点

1. **五条独立随机流**：骰子 / 事件 / 抽卡 / 际遇 / 修正。任一流推进不改变其余四流的序列——这是「同一操作序列可复现」的技术前提，也是删项审计、平衡扫描能做统计比较的原因。引擎支持按名注入常量生成器。

2. **剧本是纯数据，引擎不认识任何具体人物。** 新增剧本禁止改引擎。加载期有一批拒载级校验：条件键必须在词表内、选项跳转目标必须存在、伏笔必须有可达的置位来源、事功表未命中必须有剧本显式声明的默认处理、印章必须在五值词表内。

3. **界面层与规则层严格分离。** `engine.txt` 不引用任何 DOM；七个界面脚本经 `ui-core` 读写引擎。移植到别的引擎时，规则层可整体搬运，界面层需要按目标引擎重写。

4. **UI 层可直接丢弃。** 若只需要验证玩法正确性，`engine.txt` + `04-data/` + `05-verify/` 就够了——八套回归全部不依赖 DOM。

5. **美术不在此包内。** 原型有 107 MB 资产（64 张立绘、120 枚成就图标、印章、书法字体子集），纯文本无法携带。移植时界面需自备素材。

## 数字的可信度

`06-reports/` 里的 JSON 是批量模拟的真实输出，涵盖五剧本 × 各难度 × 多种子配置。它们不是示例数据，是这个项目用来判断"数值是否失衡"的证据。

其中 `balance-report-hardcore.json` 与 `balance-report-normal.json` 体现了设计上的一个反直觉之处：**硬核是总分系数最高的难度**（1.25，对普通 1.0、剧情 0.8），因为它危机更重、修正更狠、不能回溯、信息全盲——玩家在这种条件下打出好局，理应拿到更高评价。评级不是难度指标。
