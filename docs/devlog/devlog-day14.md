![轮次存档](workspace://assets/images/devlog/day14-save.png)

DAY 13 把六个页面搭起来了。今天做的是**把"存档"这件事做对**——以及一堆页面级的对齐。

## 一、核心改动:存档语义换代(v2.2.0)

### 旧语义的问题

原来的存档是**章首档**:导出的是"这一章开始时"的快照,读档 = **回到本章开头**。

问题是:**一章里有 3–5 轮经营,每轮 3 张牌。** 玩家玩到第 4 轮,想存个档去吃饭——回来发现**前 3 轮白打了**。

这不是 bug,是设计时就那么写的。但它在"每章多轮"的实际节奏下,体验是错的。

### 新语义:两件套

v2.2.0 把存档改成 **snapshot + live** 两件套:

```
snapshot  章首快照(供章内回溯用)
live      当前时刻的全量状态(发牌/相位/随机轨迹)
```

读档回到**存档那一刻**,不再是"回到本章开头"。

### 最硬的一块:随机轨迹也要存

这是这次改动真正的难点。

原设计里有一条原则写得明明白白:

> **回溯恢复历史状态,不恢复随机命运**(不存 rng 状态,章首重入不保证相同随机序列)

理由是 SL 问题:如果随机数能存能读,玩家就能"穷举读穿骰子"。

但**跨会话存档是另一回事**——你存了档关掉游戏,明天打开,总不能让世界重新掷一次骰子。

所以 v2.2.0 的取舍是**分开对待**:

| 场景 | 随机数 | 理由 |
|---|---|---|
| **章内回溯** | **不存**,重新掷 | 防 SL:可以试错,不可重播 |
| **跨会话读档** | **存**,原样续接 | 存档是"暂停",不是"重开" |

`SPEC.md` 里那一行被改成了:

```
回溯恢复历史状态,不恢复随机命运(……设计原则;
**跨会话存档自 v2.2.0 起相反**:rng/派生流状态随档存取,
读档续接存档时刻的随机序列)
```

### 实现:让 rng 可序列化

要让随机状态能进存档,rng 得能取出/写回内部状态。加了一对方法:

```js
function makeStateRng(seed) {
  var f = function () { ... };
  f._getState = function () { return a | 0; };   // 取出内部状态
  f._setState = function (s) { a = s | 0; };     // 写回
  return f;
}
```

主 rng 与**已派生的流**(risk / event / corr)的状态都随档存取。

### 四类相位的 round-trip 测试

新语义最容易错的地方是"相位"——存档时可能停在四种不同相位上:

| 测试 | 存/读的位置 |
|---|---|
| A | **round** —— 第 1 轮落定、第 2 轮已发牌时存;读档后相位/手牌/倒计时/属性/计次一致 |
| B | **随机轨迹** —— 同一存档读进两个新对局,后续同操作同结果(逐位一致) |
| C | **choice** —— 抉择中存档;读档仍在抉择页,可取消可落定 |
| D | **summary** —— 章末结算中存档;读档视图一致且可推进下一章 |

**B 是最关键的一条**:它证明"随机轨迹真的随档恢复了"——同一份存档读两次,后面走一样的操作,结果必须**逐位相同**。

## 二、顺带补上的两道校验

改存档时把两个旧的漏洞一起补了。

### ① 剧本身份绑定(scenKey)

五剧本的**属性维度同名**(都是那十一维)。原来的校验**只看难度**,于是:

> 跨剧本的档可以被导入他本对局 —— 带着**别人的 flags 与 eventId** 进入不可达内容,并覆写本剧本的存档。

补上 `scenKey` 校验。旧档(无此字段)按缺省放行,兼容 v2.0.1 及更早。

### ② 脏档拒收

存档存在 `localStorage` 里 —— **是不可信输入**。关键字段的类型与范围都要校验:

```js
if (!this.d.ATTR_NAMES[ak2]) return false;                    // 未知属性键 = 跨剧本脏档
if (!numRange(s.attrs[ak2], 0, this.attrMax(ak2))) return false;  // 范围须落在本剧本 per-attr 上限内
```

相位也加了白名单:`home` / `ending` 没有可恢复的对局视图,未知相位按坏档拒收。

- **行动池发牌 3 → 2**,另可附 1 张次级抉择卡(不占池)

- **底部固定 4 占位**:关键卡不再占位(挪入文本区提示条),行动卡补到 3 张;抉择卡/求医卡各替换一个行动卡位
- **治病卡**(v1.8):染病时额外发一张「求医问药」,不占行动池、不入收益递减,但占一个发牌位
- **累积式叙事**(2026-10-14):剧情卷轴的正文容器**跨相位常驻**,小节依次往下排
- 顶栏右侧**不再放段位小字**(对齐效果图:偏离只在右栏底部)

### 一个"叠层"bug

`session.ts` 里加了 `dispose()`:

> 对局离场时必须调:`bar`/`main` 都是**常驻壳节点**,挂上去的回溯按钮与 `pointerdown` 监听不摘掉的话,**每开一局就叠一层** —— 旧按钮的闭包还绑着旧 `Game`,点了会污染正在进行的对局。

这是"常驻壳 + 每局重建内容"这种架构的典型陷阱。

## 五、评级:5 级 → 10 级

数值侧今天也动了一处:**评级从 5 级改成 10 级**。

```
旧:S≥85 / A≥70 / B≥55 / C≥40 / D
新:甲上≥95 / 甲≥90 / 甲下≥85 / 乙上≥80 / 乙≥70 / 乙下≥60
    丙上≥50 / 丙≥40 / 丙下≥30 / 丁<30
```

**顶部 5 分一档,中下部 10 分一档。**

理由在 GDD 里:

> 固定等级=奖品清单,S 是某个结局的名字,被评的是**编写者押的题**不是玩家给的卷 —— 同一结局在"一手好牌做成的善终"与"众叛亲离边缘保住的善终"两个周目**必须不同分**。

等级粗了,这个区分度就出不来。所以顶部加密(高分段的区分更重要),中下部保持 10 分档。

顺带把文案统一成中文档名(甲/乙/丙/丁),和游戏内的印章用词对齐。

## 今天最值钱的一条

**"存/读"不是"保存数据",是"保存状态机"。**

我一开始以为轮次存档就是"把更多字段塞进 JSON"。做下去才发现真正的难点是:

1. **相位** —— 存档时可能停在四种不同相位,每种都要能恢复
2. **随机轨迹** —— 不只是"存几个数",是"让随机流能在另一个时间点续接"
3. **可信边界** —— 存档来自 `localStorage`,是**不可信输入**,字段类型/范围/相位都要校验

**一个"存档功能"的复杂度,几乎等于它要保存的那个状态机的复杂度。** 这也是为什么四类相位的 round-trip 测试一条都不能少 —— 漏掉任何一类,玩家就会在某条路径上遇到"读档后卡住"。
