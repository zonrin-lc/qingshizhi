## 一个新玩法:抉择卡(次级关键事件)

DAY 9 末尾我提过这个想法:**在关键事件之间,想加一类新的行动卡** —— 点选后不直接给属性增减,而是**进一段剧情、给几个选项,选完才结算**。可以理解成"次级的关键事件"。

当时我卡在**内容**上(剧情和选项得有人写),我说"这活我编不了"。

**今天,内容补齐了。每本剧本 12 张,五本共 60 张。**

### 数据结构

抉择卡挂在行动卡上,多一个 `choice` 字段:

```lua
{
  id = "ACT-C1", name = "故旧登门",
  choice = {
    segs = { "故旧登门,鹑衣百结,言家中断炊三日…", "那半块饼,是你这一生最早记下的一笔人情。" },
    options = {
      { t = "倾囊相济", eff = { attrs = { caifu = -5, shengwang = 3 } },
        res = "你把柜中积储倒出大半…乡里的秤,从来称得出人心。" },
      { t = "量力贷之", eff = { ... }, res = "…" },
    },
  },
}
```

### 引擎侧:三个阶段

新增 `phase = 'choice'` 阶段,和关键事件平行:

| 方法 | 作用 |
|---|---|
| `playCard` | 遇到 `a.choice` **不结算**,先切到 `choice` 阶段、记下 `pendingCardId` |
| `getChoiceCard` | 取剧情与选项,供 UI 渲染 |
| `chooseCardOption(i)` | 选项落定 → 应用 `eff` → 走常规结算 |
| `cancelChoice` | 中途退出 → 回到 `round` 阶段 |

### 发牌调度:每两轮强制发一张

抉择卡不是随机撞上的,而是**每两轮必发一张**,保证玩家不会漏掉:

```lua
self.choiceGap = (self.choiceGap or 0) + 1
if #crest > 0 and self.choiceGap >= 2 then
  cpick = crest[floor(deal() * #crest) + 1]   -- 强制占一个发牌位
  self.choiceGap = 0
end
```

**随机流口径**很关键:只有**强制发抉择卡时**才多消耗一次 `deal()` —— 这样和 JS golden 侧**严格同序**,对拍不会因为新玩法而分叉。

### 三条容易写错的规则

**① 落定后整局不再发,但"取消"不算。**

`choiceUsed` 只在**抉择落定**时写入;中途取消(搁置)不写,所以那张卡**还在池子里**,下次还能遇到。语义正确。

**② 必须从 pool 里剔除,不能只过滤候选。**

我一开始只在"强制发牌候选"里过滤了已用的抉择卡 —— 但它们**仍留在 pool 里**,会被下面的"常规抽 3 张"选中,打出后**二次进入 choice 阶段重复结算**。

> `choiceUsed` 只挡住强制发牌位,**挡不住常规抽牌**。必须先把已用的从 pool 移除。

**③ 取消要能回到原状态。**

`cancelChoice` 清掉 `pendingCardId` 并把 phase 切回 `round`,否则玩家会被卡在剧情页出不来。

## 顺带修掉的四个真 bug

写抉择卡的过程中,顺手在引擎里揪出四个既有问题:

| # | 问题 | 后果 |
|---|---|---|
| 1 | `enterChapter` 的 mutations **静默丢弃 `zg` / `zgSet`** | 荆轲的 `xielou`、`cuixing` 两处**戒心异变完全失效** |
| 2 | 行动卡 `chapters` 缺省写死 `{0, 6}` | 章节数 **>7** 的剧本会**漏发行动卡** |
| 3 | `riskWord` 前向声明缺失 | 调用被解析到全局 nil,**运行时崩** |
| 4 | 存档 `importSave` **校验中途失败不恢复 chapterIdx** | chapterIdx 已换新、eventId/attrs 仍是旧局 → **后续静默错配** |

第 4 个尤其阴 —— 校验失败时 `chapterIdx` 已经被改了,但**没有恢复**。之后任何 `chapter()` / `findEvent` 都会读到错配的状态,**不报错,只是结果不对**。

修法是把所有 `return false` 换成 `return reject()`,而 `reject()` 会先把 `chapterIdx` 还原。

## 存档:改成原子写

`Store.write` 原来是**直接覆写**存档文件。如果在写入途中崩溃/断电,会留下**截断的 JSON** —— 那种文件能通过 `FileExists`,但解不出东西,读档侧只能整份丢弃、**玩家进度归零**。

改成**先落 `.tmp` 再改名**:

```lua
local f = File(dest .. ".tmp", FILE_WRITE)
f:WriteString(txt); f:Close()
if fileSystem:Rename(tmp, dest) then return true end
-- 部分平台的 Rename 不覆盖已存在的目标(第二次以后的存档即属此列)
if fileSystem:FileExists(dest) then
  fileSystem:Delete(dest)
  if fileSystem:Rename(tmp, dest) then return true end
end
```

**改名是单一操作,不会留下"写了一半"的存档。** 最坏情况退回直接覆写 —— 与修复前一致,不会更差。
