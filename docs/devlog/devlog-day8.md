今天没有一个新玩法。整天都在做同一件事:**把"已经能跑"的东西,变成"看着对"的东西**。

而这一天的敌人,全都长着同一张脸——**它们不报错**。构建全绿、日志干净、游戏起得来,只是某条线不见了、某段字没出来、某个角露出去了。七个 bug,七个都不崩。

## 七个不崩的 bug

我把它们排在一起,因为查完之后发现:**七个里有六个,根因是同一个无知**——我对布局引擎默认值的想象,和它真实的行为不一样。

| # | 表象 | 真根因 |
|---|---|---|
| 1 | 小标题「选择剧本」只有金线和菱饰,**文字整段消失** | `Divider` 里的 `lbl` 没传 `wrap=false`。`whiteSpace="normal"` 在宽度不定时,把文字折进 0 宽度 |
| 2 | 两条金线**整根不见** | `Divider` 用 `width="100%"`,但父级是内容自适应列 → 百分比解析成 `auto` → 两个 `flexGrow` 金线分不到宽度,宽 0 |
| 3 | 立绘从卡片**抹角处露出去** | 库的 `overflow` 裁剪走 `nvgIntersectScissor`,**只能裁矩形**;`borderRadius + overflow:hidden` 对 `backgroundImage` 无效 |
| 4 | 罗盘中心一块**半透明方块** | 同因:图片按矩形填充 + 矩形裁剪,圆外的四个方角残留 |
| 5 | 匾额里的竖排局名,**「仓」飘到匾额上方** | 字号按卡高定,没按**字数**自适应——4 字名比匾额本身还高 |
| 6 | 顶栏整体**偏下** | 顶部留白按 `vw×3%` 算。横屏下 `vw×3%` 折算成高度是 **5.3% 屏高**,不是 3% |
| 7 | 难度胶囊悬停,**边框外有东西** | 胶囊是尖头形制,阴影只能按圆角渲染——圆弧总比尖角宽,负 spread 也压不住 |

第 1 和第 2 是**同一个组件**的两层坑,我第一遍还修错了方向:第 2 条我以为是"1px 矩形被缩放舍成 0 高",改成描边线,**还是不见**。第二次才想通是**宽度**塌陷,不是高度。

第 3 和第 4 也是同一个根:**矩形裁剪裁不了非矩形**。第 3 条的解法是自己写了个按**路径**裁剪的图片控件——第 4 条则更简单,直接用**圆形路径**填充图片,路径即圆,圆外自然不画。

**记两条纪律**:

- **横屏布局,左右边距按屏宽算,上下边距按屏高算。** 混用会在 16:9 上放大 1.78 倍。
- **百分比宽度只在父级宽度确定时有效。** 父级是内容自适应(靠 `alignItems` 居中)时,`100%` 会解析成 `auto`。

## 一只罗盘,转了四遍

![罗盘四版](workspace://assets/images/devlog/day8-compass.png)

选择页的朝代罗盘,今天改了四遍。四遍**都不是我想通的,是你指出来的**——和 DAY 7 的布局三次改版一样。

| 版本 | 交互 | 被否的原因 |
|---|---|---|
| 一 | 点中朝代,**自动**转到正上方 | 不像罗盘,像下拉菜单 |
| 二 | **拖拽**跟手转,松手吸附最近一格 | 吸附太慢,停不稳 |
| 三 | 改成**拨盘弹簧**:冲过目标一点再回摆;底板**整体旋转** | 指针和菱饰不跟着转,像"字在绕圈、盘不动" |
| 四 | **两段动画**:①底板先转,指针**指认**到该朝代;②再整体归位 | 这是你要的 |

第四版有个数学上很舒服的性质。要做到"指认 → 归位"两段,必须把角度拆成**两个变量**:

- `base_` —— 盘面旋转量。指针烘焙在底板顶部,所以指针绝对角 = `TOP + base_`
- `nameOff_` —— 朝代名的基准角,第 i 项名在 `nameOff_ + (i-1)·step`

归位时**两个一起转回**,两者的相对角不变 —— 所以**指针全程锁在选中的那个名字上**,不会出现"归位过程中指针指错"的跳变。一个拆分,省掉一整类状态同步 bug。

顺带抓到一个**既有 bug**:指针事件的坐标是**控件局部**的,但原来的点击判定拿它去减 `GetAbsoluteLayout` 的**绝对**中心 —— 也就是说,**点环上的位置,方位算出来是错的**。改成用控件自身尺寸,和事件坐标同一坐标系。

## 一个不是我的 bug

预览日志里一直有一条:

```
ERROR: Error executing Lua module 'LuaScripts/Utilities/Previews/Isolation_Client':
       :186: attempt to index a nil value (local 'class')
```

我一开始怀疑是自己的资源有问题,改了两轮都没消。

后来换了思路:把引擎那个 **94MB 的 `.data` 包**扒开,找出模块源码。第 186 行是 `local orig = class[methodName]` —— **调用时传进来的 `class` 是 nil**。

而决定性的是**引擎自己写得不一致**:同一份代码里,兄弟函数 `BlockMethod` / `BlockProperty` / `RemoveMethods` **全都有** `if not class then return end` 守卫,**唯独 `WrapPathMethod` 漏了**。引擎作者明确知道"类可能是 nil",只是忘了这一个。

又查了当天刚发布的 `latest` 引擎版本(1.32.38)——**同一行一字不差,仍无守卫**。升级修不好。

**这条只能报给引擎侧,修法是一行。** 而我们这边其实没受影响:日志显示,报错之后 110 毫秒就是我们自己的启动输出 —— 引擎用 `pcall` 把它兜住了,游戏照常起。**一个不崩的 bug,连引擎自己都不打算崩。**
