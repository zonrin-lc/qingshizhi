## 一、配音:从"部分覆盖"到"全量覆盖"

DAY 11 的 `voice-manifest` 只认三类:**主线章节 / 抉择卡 / 结局**。真跑起来立刻发现——**随机事件、危机事件、历史修正(反噬)全是哑的**。

这三种恰恰是玩家**最需要声音**的地方:随机事件是突如其来的插曲,危机是生死关头,反噬是"你逆天改命的代价"——**默片一样滑过去,情绪全丢了**。

### 给 manifest 加一层结构

原来的结构是 `chapters[剧本][章节]`,装不下"不属于任何章节的事件"。加一层 `specials`:

```
specials[剧本][事件id] = { segs = {正文音频...}, opts = {选项结算音频...} }
```

覆盖三类事件:

| 事件类型 | 数据来源 | 事件 id |
|---|---|---|
| 随机事件 | `RANDOM_EVENTS` | `R-1` … `R-12` |
| 危机事件 | `CRISIS_EVENTS.plots` / `.death` / `.qingsuan` | `C-1` … `C-DEATH` |
| 历史修正 | `CORRECTIONS` | `corr1` … `corr9` |

### 反噬事件的 id 是**算出来的**

修正事件(反噬)本身**没有 id**——`CORRECTIONS` 是个数组,条目只有 title/segs。

音频文件得有名字,所以**用下标当 id**:`corr1` / `corr2` / …

但引擎侧拿到的是**条目对象**,不知道自己是第几个。所以在 `engine.lua` 里反查下标:

```lua
-- corrId:该修正条目在 CORRECTIONS 中的下标,供配音查表(specials 的 corr<N>)
local corrId = nil
for i = 1, #self.d.CORRECTIONS do
  if self.d.CORRECTIONS[i] == c then corrId = i break end
end
self.correction = { …, corrId = corrId and ('corr' .. tostring(corrId)) or nil }
```

**反噬事件走的是同一条路**——它复用 `CORRECTIONS` 的条目,所以也要查同一个 `corrId`。

### 查表要分两条路

`game.lua` 里三处播放点都得改成"先查主线,查不到再查 specials":

```lua
-- 事件正文
Voice.Play(Voice.SegPaths(sid, ch.id, ev.id) or Voice.SpecialSegPaths(sid, ev.corrId or ev.id))

-- 选项结算
local p = Voice.OptPath(sid, gg:chapter().id, gg.eventId, i)
       or Voice.SpecialOptPath(sid, gg.eventId, i)
Voice.Play({ p })
```

`ev.corrId or ev.id` —— 反噬事件用算出来的 `corrId`,其余用自带的 `id`。

## 二、五首主题曲

### 双轨设计:先伴奏,后开唱

每曲分**两条音轨**——无人声版(inst)与有人声版(vocal)。播放顺序是:

```
进对局 → 从头播无人声版 → 放完接有人声版 → 有人声版放完回无人声版,如此循环
```

**为什么不直接循环人声版**:人声版有词,反复循环会烦。所以**第一遍先给伴奏**(进入状态),**第二遍开唱**(点题),之后回伴奏循环(**不打扰**)。

两个工程细节:

- **朗读时自动压低 BGM**(`DUCK = 0.45`)——否则人声与朗读抢耳
- **人声版临近结尾提前 1.5 秒切回伴奏**(`LEAD`)——避开尾奏留白,衔接更顺

还有一处:**引擎不暴露音频精确时长**,循环点判不了。所以时长是**用 ffprobe 量出来写死在曲库里**的:

```lua
lisi = { inst = "…", vocal = "…", durInst = 203.59, durVocal = 236.95 },
```

### 五首,五个切口

第一版写完我**自己不满意**——因为写成了**生平全景**:序章、少年、发迹、巅峰、败亡,一段不落。

**那不是歌,是百科词条。**

重写时立了五条原则:**史实准确 / 新切口 / 去辞藻堆砌 / 重韵律 / 立意明确**。核心是**「去百科化」——一首歌只取"那一刻",不做全景罗列**。

## 今天最值钱的一条

**"全覆盖"不是把已有的做多,是把没覆盖的找出来。**

我原以为 DAY 11 的配音系统"做完了"——主线有声音,感觉挺完整。真跑起来才发现**三类事件全是哑的**,而且恰好是最需要声音的三类。

**一个功能"看起来完成了",和"所有路径都有覆盖",是两件事。** 前者看主线,后者得**把系统的每一条分支都走一遍**。

写歌也是同一个道理:**"写全"和"写准"是两件事。** 第一版五首我"写全"了(生平一段不落),但没有一首"写准"(没有切口)。删掉四分之三,只留那一刻,歌才立住。
