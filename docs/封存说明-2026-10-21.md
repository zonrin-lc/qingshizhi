# 封存说明 · 2026-10-21(Lua 引擎版下线)

- 决策:**TapTap 制造的项目只保留 H5 一条线**。Lua / UrhoX 引擎版正式下线,
  相关文件整体挪进 [`封存/lua-2026-10-21/`](../封存/lua-2026-10-21/),
  打成 zip 一并留档(同目录 `lua-2026-10-21.zip`),不再维护。
- 与 2026-10-12 那次封存的区别:那次封存的是「载体从 Lua 切到 H5」之前的 Lua 工程,
  当时还留着作 JS↔Lua 对拍;这次是**把对照用的那一份也一并收走** ——
  TapTap 制造只吃 H5 包,留着 2MB 的 Lua 代码与一堆对拍脚本只是噪音,
  而且它们中间还咬过一次人(见下)。

## 留着的、**别动**的

- `prot/lua-data/*.json` —— **现役剧本数据真源**。名字里的 "lua" 是历史遗留,
  数据本身是 JSON;`h5/vite.config.ts` 的 `@data` 别名直接指向它。
- `prot/engine.js`(规则真源)、`prot/*-data.js`(H5 吃的数据产物)、
  `prot/sync-data-js.js`(生成器)、`prot/verify-data-js.js`(门禁)、
  `prot/test-*.js`、`balance-sim.js`、`path-stats.js`
- `prot/index.html` + `prot/js/ui-*.js` + `prot/server.js` —— **JS 原型**调试壳(不是 Lua)

## 门禁怎么换了

| 原来(Lua 侧) | 现在 |
|---|---|
| `prot` 的 `verify:syntax` / `verify:api` / `verify:replay` | `npm --prefix prot run verify` → `verify:data` → `node prot/verify-data-js.js`(JSON ↔ JS) |
| H5 `prebuild` 跑 `p1-verify.js`(JSON ↔ Lua) | H5 `prebuild` 跑 `h5/scripts/verify-data.mjs` → `prot/verify-data-js.js` |
| 改数据的顺序:p1-golden → p1-convert → 校验 | 改 `prot/lua-data/*.json` → `node prot/sync-data-js.js` → `node prot/verify-data-js.js` |

## 为什么要走这趟(不只是"清理")

1. **`dump-lua-data.js` 是个雷**:它是把现役数据真源从陈旧 Lua 副本**拉回来**的唯一路径。
   2026-10-21 改李斯 ACT-7 文案时就踩过 —— 改了 `prot/lua-data/lisi.json` 与三份产物,
   唯独漏了 `scripts/qingshi/data/lisi.lua`,于是两份内容分叉;而当时的校验
   (`p1-verify`)比的是 JSON↔Lua,两边一起旧就照样绿。Lua 线一旦还在,这种雷就一直在。
2. **门禁绿灯是假的**:对拍基线 `golden.json` 比引擎旧了 21 小时,
   `p2-replay` 验的是"旧 JS vs Lua",当前引擎从未与 Lua 对拍过。
3. **TapTap 制造只吃 H5 包**:留着 2MB 的 Lua 代码、对拍脚本与 wasmoon 依赖,
   对产物没有任何贡献,却让人以为"还有一条对照线在守着"。

见 [`封存/lua-2026-10-21/封存说明.md`](../封存/lua-2026-10-21/封存说明.md) 第三节。
**唯一别做的事**:拿 `dump-lua-data.js` 反向覆盖 `prot/lua-data/*.json`。
