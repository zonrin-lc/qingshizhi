## 0.3 体例纪律

1. **正文只写已确立的东西**;待决与提案一律集中在附录 A,不散落各章。
2. **名词先登记后使用**(0.2);新词缺失而自造的,回补总纲并记附录 B。
3. **举例一律抽象表述**,不举具体选项名、不举具体人物的具体选择(选项名与史实例证属剧本章/数值章)。
4. **不得描述任何未在本设计过程给过的事实**——工具形态、脚本语言、运行规模、文件结构、代码标识符;需举例用抽象句式,不虚构数字。
5. **纠错、说明、举例中出现的任何机制、数值、人名,必须可追溯到已给事实**;追不到就标注提问,不夹带。
6. 数字冲突时:**数据与规范打脸是最坏情况**——以实测数据为准修规范,并在附录 B 记录替换。
7. 与 v0.9 口径冲突:实现层面听 v0.9,设计意图层面听本文档。

- 想懂"为什么" → 01–06;想懂"是多少" → 04;编剧进场 → 05;评审看创新 → 03 偏离度节 + 05 覆盖率指标;想知道还没定什么 → 附录 A;想知道为什么没定成那样 → 附录 B。
