## 8.1 技术选型:零依赖形态与它要解决的问题

**已确立约束**(来自设计):载体=零依赖 HTML5+JavaScript,手机浏览器直接打开即玩,也可上传 PC 端;配音用 Web Speech API(R6);竖屏优先单手可完成(R7);无任何外部服务依赖(离线可玩性——待核其成立性)。"零依赖"指**不依赖第三方运行库与构建产物**;打包形态(单文件/少量无依赖文件)待核(T-01)。

它要解决的问题不是"轻量",轻量只是表象。三个角度各一条:

**① 赛制时间(21 天)**:工具链是工期黑洞——依赖解析、版本冲突、构建配置每一项都吃日历,且吃的是**不可预测**的日历(今天装好明天崩)。零依赖把构建环节的方差压到近零:省下的每一天都投给内容(05 扩展成本表:事件与选项占六成工作量,那是人肉时间,工具帮不上)。**支撑:10 章里程碑的工期假设。**

**② 投稿门槛(可交付性)**:一个需要环境准备的提交,等于把"能不能玩"押在评审的耐心与设备上。零依赖的提交物=可直发的静态资源——发布链路最短、失败点最少。**支撑:赛制 H5/PC 端投稿通道(具体通道格式与限制待核 T-02)。注意:此条论证的是"链路短",不是"一定通过审核",审核规则本身待核。**

**③ 评审体验(3–5 分钟窗口)**:评审第一次打开的 30 秒内必须见到抉择页(卖点 2 的第一印象)。这意味着**首屏可玩、无需账号、无需下载、教程不挡门**(序章教学注记在页内完成,5.4.4)。**支撑:01 卖点 2 对"零延迟"的承诺从点击延伸到启动。**

**代价(如实登记,不粉饰)**:零依赖=所有非平凡能力(渲染、布局、存储、朗读、持久化)要么手写要么用平台 API——**开发时间从"集成"搬到"自研"**;跨浏览器/跨机型行为差异全部自担(兼容结论待核 T-03);没有生态兜底(出 bug 没有 issue 区可搜)。这笔代价买的是上三条收益,值不值由 10 章的交付实况检验。

## 8.2 模块边界与依赖方向

**职责分层**(这是设计要求的抽象层,不是文件结构;具体命名与落盘位置全部待核 T-04):

```
内容层(剧本包数据,纯声明)
   ↑ 只读引用
校验层(加载器:5.1.2 清单,唯一裁判)
   ↓ 放行后交
引擎层(规则解释器:回合机/判定/五条流/修正/裁剪纯函数)
   ↑ 状态变更唯一通道 ↓
状态层(局内态 · 跨局见证 —— 两域分离存储)
   ↑ 只读 ↓ 指令
呈现层(UI/输入/弹幕/朗读/分享卡)
```

**每层职责与它支撑的设计**:
- **内容层**:五本剧本的七组字段,无任何逻辑(5.1);**禁止**:引用引擎内部符号(键名映射表在本层由技术方案维护,不进 GDD)。
- **校验层**:加载即全量跑清单(字段/词表/可达性/成环/正向修正/负偏离/印章词表/条数计数),不过拒载并报具体位置;**支撑**:5.1.5"合规=纯数据,违规=体系溢出"的机器执法 + B42 拒载校验(防静默错图)。
- **引擎层**:全部规则的**唯一**实现地;对剧本零感知(不出现具体人物名/事件名的代码分支,05 纪律);随机为五个相互独立的流发生器,各自持有独立序列;**支撑**:五流分离承诺(8.4-1)、涌现可重放(05 5.1.1 裁剪层"体内禁一切随机源")。
- **状态层**:两域——**轨迹域**(手牌、倒计时、蓄势、烧毁、当局属性/偏离度;回溯=整域回滚到章首快照,随机序列不回滚)与**见证域**(成就、词条解锁、统计;回溯不清、读档不截,硬核导出恒空)。**支撑**:6.5"轨迹可以抹掉重来,见证不可以"——这句设计话在工程上就是两域的写回规则差异,存储不分离则规则无法兑现(T-05 验证两域边界)。
- **呈现层**:只读状态+发指令,不直写规则数值;弹幕、渐显、高亮、朗读、分享卡在此;**支撑**:R1/R3(反馈的时序与形态)、L1(数值不进正文的前提)。

**依赖方向规则(含"禁止项",可检查)**:
1. 内容层→引擎:**禁止**(剧本不认识代码,引擎才认识剧本结构)——违反即 5.1.5 失守;
2. 呈现层→引擎内部判定函数:**禁止直调**,一切经状态层指令通道——否则"0.5 秒反馈的时序"不受引擎控制,R1 失去工程保障;
3. 引擎→呈现:**禁止感知**(引擎产物=结算事件流,呈现自行编排节奏)——保证批量模拟可在无 UI 环境跑完(§7 T-06:无头运行能力待核);
4. 随机:五条流各自发生器,**禁止共享一个全局序列**(跨流串扰=重试换牌又换骰=8.4-1 破产);
5. 持久化:见证域与轨迹域**禁止混存同一键空间**(否则"硬核导出返回空"与"回溯不清成就"在同一次序列化里互相打架)。

## 8.3 继承:从废弃方案里保下来的那件东西

废弃的那份技术方案里,唯一值得保留的抽象=**数据驱动的人物包**。它在当前形态下的继承与改动:

| 废弃方案原样 | 继承为 | 继承时改了什么 |
|---|---|---|
| 人物包+回调(动态选项集是包内函数,如 optionsFor) | 剧本包七组纯数据字段(5.1.1);选项集被状态裁剪 | **函数改声明**:裁剪从"包代码算给引擎"倒转为"引擎纯函数读包声明"——换来可重放、可校验、可批量模拟(函数无法被加载器审,数据可以);英文标识符全面退出 GDD 正文(B27 教训) |
| 六维硬编码+隐藏值"国祚" | 十一维契约制(03)+偏离度显式化(B03) | 变量从"引擎内置语义"降为"key/label/good/init 数据声明"——五本共用一套维度语法,身外/自身的"倾向而非规则"由门槛形态承担(B10) |
| 单剧本单结局表 | 结局表+资格门+判定树三层(03/3.5) | 结局从"剧情终点"改判为"评分的一个输入":分数不查表、由整局积分(涌现落点判据) |
| 成就多条件表达式 | 单键引用三处封闭声明(06) | 复合欲改道结局变体——限制换来了"成就=历史细节"的可检性 |
| 太史公式判词等叙事装置 | 史传断语体参与朗读/分享卡(03/3.5,B43) | 独立判词元素清除,体裁本体保留——继承的分辨标准:**装置可废,体裁是结构** |

一句话:**继承的不是它的代码,是它的分层直觉;改动全部朝同一个方向——把"能执行的东西"换成"能审查的东西"。**这正是 05 零改动纪律在架构层的镜像。

## 8.4 这套架构如何贡献涌现(具体四处,不泛谈)

1. **五条独立随机流=涌现的"可证伪"前提**。涌现要可信,玩家得能检验"换一步走,世界是不是真的不同"——共享序列下这个检验永远被污染(你改了骰子也就改了牌)。独立流让"反事实重放"成为可能:固定其余四流,只换抉择→结局差异可指认为选择的果。**这是把 05 可重放验证从测试室交回玩家手里的架构决定**(玩家侧是否提供该能力=产品决策,附录待拍板 P-8)。
2. **裁剪层的纯函数约束=让"局面"可学习**。f(状态)无随机源→同一状态永远同一局面→玩家可以归因、第二局可以策略化。涌现的交互面(05 5.1.3"设计侧支撑")在架构上就等于这一条:**随机住在调度,不住在内容。**
3. **加载器=涌现语法的边界守卫**。拒载清单里的每条(负偏离/正向修正/印章表外/成环)都是"**不允许非涌现的数据进入涌现引擎**":能回滚的偏离度、会发糖的修正、自造的印章,全部进不了门。**涌现不是引擎的宽容,是输入的纪律。**
4. **状态层两域分离=时间之箭的存储形态**。轨迹域可快照回滚(章首快照,5.4)、见证域只进不滚(6.5)——一局之内的"可试错不可重播"、一局之外的"失败有尊严",最终都要落到"谁在哪次写回里被抹掉"的存储事实上。**不可逆性是一种持久化策略。**

## 8.6 工程纪律三条(可检查形式)

**① 文档先行**:凡触碰"GDD 已登记事实"(规则编号、常量、状态机、词表)的代码变更,必须先改 GDD 或在同一提交内同改;**检查法**:提交审查——diff 含引擎/内容代码但不含 docs/ 改动且触及下列锚点者退回。锚点清单=04 总表行号、02/05/06 的规则编号(C*/R*/W*/N-*/O-*)。**例外**:纯呈现层改动(不触判定与数值)免——这正是 8.2 依赖方向 2 的反向福利:边界清楚,纪律才可检查。
**② 附录制度**:正文只写已确立;待决/提案唯一收口处=附录 A。**检查法**:脚本 grep 正文各章「待决|提案|TBD|暂按」,命中数必须为 0;附录 A 每条须含【问题|影响章|拍板时点】三列,缺列退回(当前表:2 待决+8 提案+5 待锚+6 观测,全部合规)。
**③ 注释引用规则编号并防漂移**:代码注释引用 GDD 锚点时,**引用规则编号,不引用章节行号**(章节会顺延——本轮已从 30 章制改为 31 章制,行号引用全部报废过一次的等价风险,规则编号 B/C/R/N 制不受章序影响);**检查法**:定期运行核对脚本——抽取代码内全部锚点引用,逐一验证其在 docs/gdd/ 与 04 总表中存在;引用目标被删除或改名=构建失败。**支撑**:B 系列档案可追溯——每条债、每个否决都有编号,注释里写的编号就是项目记忆的外键。
