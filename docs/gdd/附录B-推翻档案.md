# 附录 B · 推翻档案(设计如何自我纠正的完整记录)

> 用途:本档案既是版本史,也是开发日志的直接素材——"AI 在自检中犯过的错、被推翻的假设,比任何设计文档都更能证明这个项目是真的在做"。提交时建议主动附上。
> 列定义:**发起方**(开发方=用户裁决 / AI=自查抓获)/ **推翻了什么** / **为什么**。

## 主题与方向

| # | 发起方 | 推翻 | 理由 |
|---|---|---|---|
| B01 | 开发方 | 单剧本"五丈原片段"→多剧本历史偏移模拟器 | 只演一个片段就定结局,对"历史人物"太薄;人物厚度需一生尺度承载 |

## 修正与反噬

| # | 发起方 | 推翻 | 理由 |

| B07 | 开发方 | 反噬=甲类旁支→乙类接管 | 与构陷同机制;且堵住"借反噬回满白赚倒计时"的形式漏洞——残酷的形式与内容一致 |
| B08 | 开发方 | 循史段"修正概率低"→完全不进入判定(真空区) | 玩家保住循史,历史就暂不算账;循史段是全作唯一"世界从不主动开口"的区间,零增量维持由此有了真实的购买物 |

## 机制与结构

| # | 发起方 | 推翻 | 理由 |
|---|---|---|---|
| B10 | 开发方 | "身外属性进选项一律硬门槛"→规则是软对能力与状态、硬对处境与事实,与属性分组无关 | 分组是找钥匙的倾向不是发牌的限制;名声高才走得通的路,不达标照样掷骰赌——承重墙级错误,所有剧本规格都会照它写 |
| B11 | 开发方 | "25–35 决策点是预算不是目标,宁可 20"→基准不可顺手改 | 越权修改既定体验规格;后由 B23 正式以实测 15–22 取代 |
| B12 | AI(开发方确认) | "反噬纯罚无酬→玩家不敢偏"论证 | 前提自设无依据;后"高段有回报"拍板结案(专属池+1.15),该推论连同前提一并作废 |
| B13 | 开发方 | 主动撤销自己上一轮的兜底指令:行动卡全锁定→重置倒计时→改为**不触发任何兜底** | 打不出牌=时间变多,设计自纠正;重置=白送时间抹平资源门槛,牌少时自旋还每转白赚 |
| B14 | 开发方 | R9 初稿"不存在先看后选"→"必须完整呈现:未读完不得出现选项" | 与逐句渐显自相矛盾(渐显本身就是先读后选);R8 管开启前不许偷看,R9 管开启后必须看完,两头堵死 |
| B15 | 开发方 | 修正触发"逐条独立判定"→两步制:先判来不来(过线取数),再均匀抽来哪条 | 字段语义钉死:条目概率只管来不来;段位决定节奏(微澜间歇/改流准点/逆天翻倍),内容永远纯运气 |
| B16 | 开发方 | C1"每选项必含属性+历史侧双效果"→拆 C1a 防装饰/C1b 配比观察 | 实测 67% 效果块为纯属性经营,旧条判负三分之二内容;而**三成历史侧正是设计成就**——每步改史则循史不存在。规范与数据打脸是最坏情况,以数据为准修规范 |
| B17 | 开发方 | C10"≤60 字硬上限"→分级(60/100 带+节点专用+豁免清单) | 28% 存量文本超限会被一刀砍;0.5 秒铁律管反馈出现的时间,不管读完的时间 |
| B18 | 开发方 | 决策点方案 A(出牌计入)/B(分层口径)双驳回→方案 C:事件抉择页唯一计入 | 决策点衡量"真正需要想的问题"的个数,不是点击数;掺入操作次数则与时长成正比、零信息量 |
| B19 | 开发方 | "行动卡不设险招"→**恢复可设软门槛险招**(同套掷骰烧毁) | 上上轮只抽查三张行动卡、样本当全貌;真实差别收窄为一条:财富在行动卡=支付硬检查。连带升级:行动卡的赌不吃蓄势加成→"攒牌面/赌命"是可支配资源的差异 |
| B20 | 开发方 | 容错描述跨本套用(项羽"苟活容错最高")→各按自身结构单独描述 | 项羽官方容错 0–1:活路(江东偏安)恰恰要求人物性格的自杀,逆人格的苟活每步加门槛;容错悖论成为"绝不跨本套用"的示范案例 |
| B21 | AI | 「硬核定位」违反自立的"高难与硬核不同屏"纪律→改「绝径」+命名交叉检查拒载 | 自设的纪律自己先违反,且错误伪装在合理表内——定位词表×难度档表任一字面重合=命名事故 |
| B22 | 开发方 | 政绩"功业计分的自然轨道"→不进公式,降级为门槛与结算内容 | 事功表=离散事件计分,政绩=连续状态值;合并即造"刷政绩刷功业"漏洞——功业必须来自成事,不是积累 |
| B23 | 开发方 | 25–35 决策点作废→实测 15–22;时长基准不变 | 错的不数据,是锚:旧数从心流节奏倒推、从未与事件总数对账;验算 1.8–4.0 分/点×15–22 恰落 40–60 分基准内 |
| B24 | 开发方 | 难度系数剧本可覆盖(开放两列)提案→五列全局锁定 | 危机系数可覆盖,"硬核危机更重"就不再是硬核定义,沦为作者偏好;跨剧本评级可比是一个 S 在任何剧本里都是同一个 S 的前提 |
| B25 | 开发方 | 事件数区间按剧本类型分档提案(自查中曾考虑)→全局统一不分档 | 每章数=节奏约束非密度约束:它保证"章"这个体验单元心跳均匀,分档破坏单局时长可预测性,而可预测性正是验收表依赖 |
| B26 | 开发方 | 章=时间切片的隐含假设→**章=幕**(机制不感知年历) | 跨度从一年半到七十年靠旁白锚时间;实测每章事件数基本等量=密度自适应是数据自己长成的,行动卡泛化性由此证实 |
