
即：**5 本剧本全部触发**，共 64 处引用、60 个去重成就 id 缺图。

> ⚠️ 运行目录很重要：`node prot/test-ui-contract.js`（从仓库根跑）会以
> `ENOENT: ./package.json` 崩溃，那是 cwd 导致的假象，不是真实失败。
> 该文件的其余 `require('./…')` 走的是**模块目录**，唯独第 5 项用
> `fs.readFileSync('./package.json')` 走 **cwd**。
> **正确姿势：`cd prot && node test-ui-contract.js`**，或用 `prot/package.json` 的 `npm test`。

## 二、根因

契约要求每个成就 id 都有 `assets/ach/ach_<id>.png`。实际：

- **`assets/ach/` 目录根本不存在**（不只是缺个别文件）
- `git log --all -- assets/ach` 命中 **0 条**——该资产类**从未进入过版本控制**
- 因此这不是「资产被误删」的回归，而是「这一整类美术资产从未入库」

测试自身的豁免机制印证了这点：

```js
/* 8. 成就图标契约 … 豁免清单：美术批次未交付项
 *    （已在美术资产清单 v0.2 登记、UI 有 onerror/无名目兜底），交付后从豁免中移除。 */
const EXEMPT = { xiangyu: ['gai'] };   // 当前仅豁免 1 个
```

`EXEMPT` 是为「美术批次未交付的**个别项**」设计的逐项豁免。目前 `assets/ach/`
整类缺席，性质不同——不是个别项待交付，而是该资产类整体未入库。

## 三、为什么现在没修

1. **补图属于 P3（美术复刻）范围**，不在 P2（最小可玩闭环）内。
2. **不应把它们塞进 `EXEMPT`。** 逐项豁免是交付清单的性质：把 60 个 id
   一次性写进豁免表会让这条契约永久变绿，把「整类资产缺席」这个真实缺口
   永久掩盖掉，且违背注释里「交付后从豁免中移除」的自我约束。
3. **无法就地伪造。** 造占位图能骗过测试，但会让「数据有、图有」这条
   防破图契约失去意义。

## 四、修复路径（待 P3）

1. 产出 `assets/ach/ach_<id>.png` 共 60 个（见下表分组），或
2. 确认走文本/印章式成就呈现（不依赖位图），则**改契约本身**而非补图——
   这需要先定呈现方案，不能由测试侧自行降级。
