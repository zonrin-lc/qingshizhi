## 二、高危问题（已人工核实）

### H1. 「回溯」按钮每开一局累积一个，旧按钮仍绑定旧对局

`h5/src/game/session.ts:56-57` — Session 构造函数 `mounts.bar.append(this.backBtn)`，但全仓没有任何代码移除上一个 Session 的 backBtn（grep 确认只有这两行 + CSS）。`shell.bar` 是常驻元素，第二局起顶栏叠出 N 个「回溯」按钮；更糟的是旧按钮的 onClick 闭包绑定**旧 Session/旧 Game**，点击会对旧对局执行 backtrack 并 renderIntro 到当前容器，污染正在进行的对局 UI。

**建议**：给 Session 加 `dispose()`（移除 backBtn、移除 pointerdown 监听），在 mountGame 覆盖前调用；或把 backBtn 做成 shell 级常驻单例，Session 只更新它。

### H2. `wireBack` 每次开局在常驻按钮上叠加 click 监听

`h5/src/main.ts:312` + `h5/src/shell/shell.ts:98-101` — 顶栏返回钮是常驻 DOM，每局 `addEventListener('click', …)` 且从不移除。第 N 局点「返回」会同步触发 N 次 `goSelect()`。当前回调幂等所以侥幸不崩，但监听与闭包无限累积。（两个审查代理独立发现同一条。）

**建议**：`buildShell` 里只绑一次、回调走可变引用；或 wireBack 内部先移除旧监听（AbortController / replaceWith 克隆）。

### H3. 存档页「存 入」是永远走不通的死功能 + 返回路径丢进度

`h5/src/main.ts:246-252` —
- `onSave` 在 `!session` 时 toast「没有进行中的对局，无法存入」，但 `goSaves()` 的所有入口都先经 `goMenu()`/`autosaveIfPlaying()` 把 `session = null`——**玩家永远无法手动存档**，存档页空档上的「存 入」按钮（savepage.ts:96-99）点击必失败。
- `onBack: () => (session ? goGame(curKey, 'normal') : goMenu())`：`goGame` 不带 preloaded 会 `new Game()` 从第一章重开，**本章进度丢失**；难度还硬编码 `'normal'`，硬核/剧情难度玩家返回后难度被悄悄改写。

**建议**：短期先移除/禁用存入按钮并修正文案；正确解是让对局中能进存档页（session 存活时 `session.renderTop()` + `showGame()` 复用原 session 返回），存入走 `session.game` 真实难度。

### M1（数据层）。启动自检抵消剧本懒加载的全部收益

`h5/src/main.ts:49-61` — `checkData()` 启动时**串行**拉全部五份 JSON（合计 ~280KB gzip），`scenarios.ts` 的按需加载设计形同虚设，首屏被迫下载全部数据。注释自承是刻意取舍，但至少应 `Promise.all` 并行。

**建议**：把「五本数据齐全且字段合法」的校验前移到构建期 `verify-data.mjs`（加纯 Node 的 JSON 结构校验），运行时 checkData 删除或降级为只校验当前入局剧本。

### M2（数据层）。`__APP_VERSION__` 注入了却没人用，版本号仍是手抄的第三份

`h5/vite.config.ts:33-35` define 注入了 `__APP_VERSION__`，注释专门警告「版本号漂移事故」；但 `h5/src/game/settings.ts:13` 又手抄 `APP_VERSION = 'v2.2.0 · H5 版'`，`__APP_VERSION__` 全仓零引用。下次 prot 升版本，菜单/设置页版本号将静默漂移——正是注释警告的事故。

**建议**：settings.ts 改用 `__APP_VERSION__`（types/ 加 declare）。

## 四、低危问题（摘要）

**核心层**：doChoose 不设 lastSettleText（回显缺失）；toast 计时器无竞态保护（连发会提前隐藏）；audio.ts `failed` 粘性（一次抖动永久禁音乐）；险招致死时仍播选项配音（Lua 跳过）；renderEnding 缺复盘列表/achNew/「再入此局」按钮（功能缺口）；gloss.ts 注释理由有误（结论侥幸正确）；voice.ts:64 注释已过时。

**UI 层**：menu/select 防御性 querySelector.remove() 绕过 destroy（若触发则 rAF 泄漏）；wheel 初始化未同步 paint 首帧堆叠；menu 每帧强制同步布局；`.portrait__name` 重复定义；game.css 与 base.css 工具类完全重复；`rgb(0 0 0 / 35%)` 现代语法与全项目 rgba() 不一致（iOS<15 webview 不解析）；`100dvh` 无 vh 兜底行；`qingshi:scale` 事件与 `--vw/--vh` 无消费者（死代码）；disabled 菜单项仍响应 hover；「入 局」二字触屏永远不可见（仅 hover 显示）；罗盘无键盘可达性；删除存档无二次确认。

**数据/测试/构建**：build-assets.py 源根写死 `D:\MUSI\SHIJU\...`，换机器连 `--only lua` 都跑不了；run-all.cjs 参数拼错时静默 `0/0 套通过` 假绿；dev-check.cjs 孤儿化（无入口会跑到）且复制了 harness 实现；save.cjs 两条断言写死 INIT 当前值（自己注释反对的写法）；`@rollup/plugin-commonjs` 是死依赖；vite.config 未设 `base`（子路径部署会全站 404，需写明前提）；`__QS__` 测试挂钩生产构建无条件暴露；tests/README.md 文档漂移；verify-data 不校验 scripts/qingshi/data 这份「封存权威源」（当前无风险，但数据流向与口头说法相反）。

## 总体评价

工程质量整体偏高：引擎集成扎实、Lua 对齐有注释有出处、数据等价门禁严密、测试有真实的回归记忆（每条断言几乎都写着「上次怎么塌的」）。**最值得警惕的模式是「注释里正确诊断了问题，代码却没跟上自己的诊断」**（懒加载被自检抵消、版本号第三副本均为此类）。问题集中在两处：页面/对局生命周期的「出口」侧（Session 无 dispose 导致跨局累积），以及存档子系统相对 Lua 版的三处实质行为缺口（手动存、结局清档、跨局收藏）。第一梯队四条修掉后，日常游玩路径即无已知阻断性问题。

### 修复后的风险备注
