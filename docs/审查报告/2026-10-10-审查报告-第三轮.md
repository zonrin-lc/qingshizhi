## 四、观察项（非缺陷，但值得决策）

### O-1　数据现在有三份副本，漂移风险已实证发生

当前数据流：

```
scripts/qingshi/data/*.lua   ← 手工维护的真正来源
   ├─ dump-lua-data.js ─→ prot/lua-data/<scen>.json   （反向导出）
   └─ p1-convert.js     ─→ prot/lua/data/<scen>.lua   （正向转换）
```

R-1 正是这套双向往返产生的漂移。而 `p1-verify` 校验的是「`lua-data/*.json` ↔ `lua/data/*.lua`」——在 JSON 改由 Lua 导出之后，**这个校验已退化为「Lua → JSON → Lua 的往返自检」**，强度比原先（校验 JS 数据转 Lua 的无损性）明显下降。

> 注：`golden.json` 是例外，它由 `p1-golden.js` 从 JS 引擎生成，`p2-replay` 的有效性不受影响。

**建议**：明确 `scripts/qingshi/data/*.lua` 为唯一事实源，`prot/lua/data/` 这一路产物若仅供 `p1-verify` 使用，考虑直接删除以消除漂移面；若保留，至少把 `p1-verify` 纳入 `npm run verify`。

### O-3　`store.lua` 错误路径仍泄漏 File 句柄

新增的 `Dispose()` 覆盖了正常路径，但两处错误路径没有：

- `Store.read`：若 `f:ReadString()` 自身抛异常（它在 `pcall` **参数求值阶段**执行，`pcall` 捕不到），`Close`/`Dispose` 都不会执行

另外 `Close()` 后紧接 `Dispose()` 属冗余（`Dispose` 语义已含 Close）。均为小问题，不影响正确性。

## 五、基准漂移评估（`golden.json` 重新生成）

对拍基准由修改后的 JS 重新生成，意味着 `p2-replay` 的 100/100 证明的是「**Lua 与新 JS 一致**」，而不再证明「与修复前的既定行为一致」。

**实测漂移范围（我逐局逐字段比对）**：

按字段: {"attrs":4}      ← 仅 attrs.weiji

**评价：漂移极小且范围完全可控**——4 局全部落在 jingke（唯一改动了 `mutations.zg` 的剧本），字段仅 `attrs.weiji`。因果链清晰：`mutations.zg` 恢复 → `zg` 变化 → `zgMax` 条件使选项锁定状态改变 → 固定决策下标落到不同分支 → `weiji` 差异。

## 六、我的一次误判（记录以备查）

我看到对方新增 `local riskWord` 前向声明，而其后是 `function riskWord(rate)`（无 `local`），判断为「局部变量永远为 nil → 必崩」的回归。

**实测证伪**：

```
CURRENT  : export.riskWord = function  | riskTitle(hardcore) = 🎲 成算七成 · 成  | _G.riskWord = nil
BASELINE : export.riskWord = function  | riskTitle(hardcore) = 🎲 成算七成 · 成  | _G.riskWord = function
```

Lua 中若作用域内已存在同名 local，`function f()` 等价于 `f = function()`，赋值目标是 local。故这是**正确修复**，且**顺带消除了原先的全局命名空间泄漏**。

我特意把它记下来：**审查里"看起来是 bug"的东西必须实测，不能靠推理下结论**——这次如果我没跑就写进报告，会误报一个不存在的严重缺陷。
