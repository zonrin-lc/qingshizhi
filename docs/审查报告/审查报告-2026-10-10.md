## 一、项目概况

文字卡牌策略游戏，单机横屏（`.project/settings.json` 中 `multiplayer.enabled=false`），UrhoX 引擎 Lua 5.4。

架构分层健康：

```
main.lua（入口，38 行）
  └── ui/shell.lua（外壳/导航/顶栏，400 行）
        ├── ui/home.lua（主页/菜单/存档/设置，691 行）
        └── ui/game.lua（对局界面，745 行）
              └── qingshi/engine.lua（数据驱动引擎，1,629 行）
                    ├── qingshi/prng.lua（mulberry32 随机数，20 行）
                    ├── qingshi/store.lua（存档读写，37 行）
                    └── qingshi/data/*.lua（五个纯数据剧本）
```

引擎与 JS golden 版本做过 100 局逐位对拍；剧本数据由 JSON→Lua 转换器机器生成（荆轲两处手写补丁除外，见 4.2）。

**静态验证总结果**：

- LSP 全量检查 41 条 Error，逐条核实后**全部是类型标注噪声**（数据表缺 `---@class` 声明、跨模块动态挂函数、Yoga 百分比字符串、`kids` 混排数组被推断为单一类型），无一条对应运行时 bug。
- 剧本图遍历 **0 严重问题**：128 个章节事件 + 60 个随机事件 + 312 张行动卡，无悬空跳转、无不可达节点、无 A→B→A 死循环、末章全部收束到结局、所有条件跳转数组都有无条件兜底分支。

## 二、严重问题（2 个，确定性缺陷，建议优先修复）

### 2.1 `importSave` 先赋值后校验，脏档会搅坏正常对局

- **位置**：`scripts/qingshi/engine.lua:1363`
- **问题**：`self.chapterIdx = obj.chapterIdx` 在 1363 行执行，但 1364–1395 行还有十余处 `return false` 校验（attrs 值类型、dev、peak、zg、attrMax 越界等）。任一校验失败后函数返回 `false`，但 `chapterIdx` 已被改成新值，而 `eventId`、`phase`、`attrs` 等仍是旧局状态。之后 `chapter()`（:192）用新 `chapterIdx` 取章、`findEvent`/`getOptions` 用旧 `eventId` 在新章里找事件，全部静默错配或返回 nil。
- **修复方向**：先完成全部校验，最后一次落盘（校验通过前不写任何 `self.*`）。

### 2.2 从存档页进对局后「返回主菜单」显示陈旧存档页

- **位置**：`scripts/qingshi/ui/shell.lua:64-72`（`Shell.showMenu`）+ `scripts/qingshi/ui/home.lua:226-228`（`showSaves`）
- **问题**：`showSaves` 把 `menuMain` 设为不可见、`menuSaves` 设为可见；`showSettings` 同理。但 `showMenu` 只把 `menuLayer` 整体置可见并调用 `renderMenu()`——`renderMenu` 只重建 `menuMain` 的子节点，**不恢复其可见性**，也从不隐藏 `menuSaves`/`menuSettings`。
- **复现路径**：主菜单 →「查看存档」→ 点存档进入对局 → 顶栏「← 返回」→ 确认 → 看到的是进入对局前的旧存档列表（`menuSaves` 仍可见且叠在 `menuMain` 之后），主菜单不可见。对局内返回确认文案（`shell.lua:55`「当前进度已保存，可随时从『继续旅程』回来」）恰好引导用户走这条路径，触发概率高。
- **修复方向**：`showMenu` 中显式复位子页可见性（`menuMain` 可见、`menuSaves`/`menuSettings` 隐藏）。

## 三、中等问题

### 3.1 引擎核心（`engine.lua`）

**3.1.1 章首属性结算不触发死亡判定** — `engine.lua:357-416`
`enterChapter` 的衰老扣体魄（:368）、门客散去扣声望、各项危机增量都可能把 `tupo` 打到 0 或 `weiji` 推过 100，但整个函数只调用危机≥90 的死亡**事件**（:440），从不调 `checkDeath()`。lethal 难度下「衰老致死」要等玩家下一次出牌/选择才被判定（:616/:666/:920），中间隔着一章的 intro。`applyEff` 内的危机一次性加成（:1028-1052）同样不查死亡，靠调用方兜底。

**3.1.2 回溯/读档后 `_weijiClamp` 残留** — `engine.lua:949`
`_weijiClamp` 只在 `makeSummary`（:1224-1227）清零。`backtrack`（:1271-1318）和 `importSave`（:1355-1462）都不重置：非 lethal 难度下危机被钳到 95 后若玩家回溯或读档，旧 `_weijiClamp` 会在下一次小结里被重复扣减，`attrDelta.weiji` 显示值错误。

**3.1.3 负 `dev` 效果被静默截断，与 JS truthiness 语义存疑** — `engine.lua:1001`
`if eff.dev ~= nil and eff.dev > 0 then`——JS 里负数是 truthy，若原版是 `if (eff.dev)`，负 dev（"回摆"）会生效，Lua 移植后 `> 0` 把负值砍掉。同时 `choose`（:926）和 `playCard`（:662）返回的 `devDelta` 会如实显示负数，造成「界面显示偏离 -5 但 dev 实际没变」的表里不一。100 局对拍通过说明测试未覆盖负 dev，或 JS 版同样截断——需对照 JS 源确认。

**3.1.4 剧本数据缺字段时多处裸索引 nil，无防御**
引擎假定数据包字段齐全，缺失即崩：

| 位置 | 裸索引 |
|---|---|
| `engine.lua:907` | `self.d.KEY_NODE_NAMES[ev.id]`（事件带 `key=true` 而表缺失时崩） |
| `engine.lua:1146` | `#self.d.CORRECTIONS`（`band > 0` 时未判 nil） |
| `engine.lua:686/918/1481` | `self.d.ACHIEVEMENTS[...]` 多处 |
| `engine.lua:225/252, 281/285` | `self.d.ATTR_NAMES` 未判 nil |
| `engine.lua:78 + 377` | `NewGame` 不校验 `diffKey`，`data.DIFFICULTY[diffKey]` 为 nil 时 `enterChapter` 的 `self.diff.wj` 即崩 |
| `engine.lua:1323 vs 1330` | `exportSave` 第一行允许 `SCENARIO` 为 nil 通过，:1330 又无条件取 `self.d.SCENARIO.id`，自相矛盾 |

修复方向：引擎加载数据包时做一次 schema 校验，一次性消除整组风险。

### 3.2 UI 层

**3.2.1 `clearMain` 顺序错误：渐显中途切页残留旧文本** — `shell.lua:116-119` 配合 `:133-143`
`clearMain` 先 `ClearChildren()` 再 `cancelReveal()`；而 `cancelReveal` 会把尚未播出的 `rv.items` 逐个 `AddChild` 回刚清空的 `mainBox`，并触发旧页面的 `done` 回调。
触发：叙事渐显（约每段 0.65s）期间点顶栏「回溯」→ `g:backtrack(); Shell.renderIntro(true)`（`shell.lua:218`）→ `clearMain` → 残留叙事段落被加回 `mainBox`，随后新章首内容追加其后——**新章首页面顶部残留上一页文本**。所有 `clearMain` 调用点（renderIntro/renderEvent/renderEndEvent/renderSummary/renderEnding）共用此顺序；正确做法是先 cancel 再 clear。

**3.2.2 确认浮层确定按钮文案硬编码为「回 溯」** — `shell.lua:321`
`Shell.confirm` 是通用确认框，但确定按钮固定写死 `text = '回 溯'`。它被三处使用：回溯（`shell.lua:214`，文案碰巧匹配）、**返回主菜单**（`shell.lua:55`）、**退出游戏**（`home.lua:113`）。后两处用户看到的确认按钮是「回 溯」，文案与操作完全不符。

**3.2.3 全部页面重建只 `ClearChildren` 不 `Destroy` → Yoga 节点持续泄漏**
`Widget.lua:1207-1217` 的 `ClearChildren` 仅 `YGNodeRemoveChild` + detach，不释放；`YGNodeFree` 只在 `Destroy()`（`Widget.lua:766-790`）中调用；Widget 类无 `__gc`。
项目所有重建入口——`renderMenu`（`home.lua:86`）、`buildRightImpl`（`home.lua:473`，每次换朝代/剧本/难度都触发）、`renderSide`（`game.lua:104`，每页都调）、`showSaves`/`showSettings`、`clearMain`/`clearOpts`——都只 ClearChildren。被 detach 的整棵子树的 YGNode 永不释放，长会话内存单调增长。项目代码全库搜索无任何 `Destroy()` 调用。需要与库的所有权语义对齐（要么重建前 Destroy 旧子树，要么确认绑定层有 GC 兜底）。
