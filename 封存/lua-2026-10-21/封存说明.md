# Lua 引擎版封存说明(2026-10-21)

> 决策:**TapTap 制造的项目只保留 H5 这一条线**,Lua 引擎版(2026-10-12 封存、
> 之后一直只作对照参考)正式下线,相关文件整体挪进本目录,不再维护。
> 需要回看历史实现或找回某段 Lua 逻辑时,从这里取;其余一律以 H5 + JS 引擎为准。

## 一、这里面有什么

| 路径 | 是什么 | 为什么下线 |
|---|---|---|
| `scripts/` | 封存的 Lua 工程(`main.lua`、`qingshi/engine.lua`、`qingshi/ui/*`、`qingshi/data/*.lua`、`qingshi/prng.lua`、`qingshi/store.lua`,含 `FROZEN.md`) | 载体已从 Lua 引擎切到 H5(Vite + TypeScript);`prot/engine.js` 是规则真源,Lua 版只是逐位移植的对照副本 |
| `prot/lua/` | 由 `prot/lua-data/*.json` 生成的 Lua 镜像(json → lua 的产物) | 只服务于 JS↔Lua 对拍 |
| `prot/p1-convert.js` | JSON → Lua 转换器 | 生成物已无人消费 |
| `prot/p1-verify.js` | JSON ↔ Lua 逐字段等价校验 | **已由 `prot/verify-data-js.js` 取代**(JSON ↔ JS 才是玩家实际吃的那份) |
| `prot/p1-golden.js` / `prot/golden.json` | 对拍基线的生成与基线本身 | 只服务 JS↔Lua 对拍 |
| `prot/p2-replay.js` / `prot/p0-parity.js` | JS↔Lua 逐局对拍 / PRNG 一致性对拍 | Lua 侧没了,对拍无意义 |
| `prot/lua-syntax-check.js` / `prot/lua-apicheck.js` | Lua 语法与 API 校验 | 无 Lua 代码可校验 |
| `prot/dump-lua-data.js` | **反向**生成器:从 `scripts/qingshi/data/*.lua` 覆盖写回 `prot/lua-data/*.json` | **危险**:它是把现役数据真源从陈旧 Lua 副本拉回来的唯一路径(李斯 ACT-7 的文案改动就被它回滚过一次)。已停用,留在本目录只作历史参考 |
| `prot/gen-voice-manifest.js` | 往 `scripts/qingshi/data/voice-manifest.lua` 写清单 | 现役清单工具是 `h5/tools/build-voice-manifest.cjs`(JS) |
| `emmylua/` | UrhoX 引擎的 Lua 类型定义(230+ 个 `.d.lua`,给 Lua 语言服务用) | 随 Lua 版一起下线;它本来就被 `.gitignore` 忽略(没进过版本库),这里只收进 zip 备用 |

## 二、留在原处、**不要**动的

| 路径 | 是什么 |
|---|---|
| `prot/lua-data/*.json` | **现役剧本数据真源**。名字里的 "lua" 是历史遗留(H5 复用 Lua 时代的目录),五个剧本的正文/卡面/结局都在这里,H5 与引擎都从它派生。`h5/vite.config.ts` 的 `@data` 别名直接指向这个目录 |
| `prot/engine.js` | 规则引擎真源(JS) |
| `prot/*-data.js` | 由 `prot/lua-data/*.json` 经 `prot/sync-data-js.js` 生成的 JS 产物(H5 吃这份) |
| `prot/verify-data-js.js` | JSON ↔ JS 等价门禁(取代了 `p1-verify.js`),已接入 `prot` 的 `npm run verify` 与 H5 的 `prebuild` |
| `prot/test-*.js`、`balance-sim.js`、`path-stats.js` | JS 侧的规则回归与模拟器 |
| `prot/index.html` + `prot/js/ui-*.js` + `prot/server.js` | **JS 原型**调试壳(不是 Lua),仍可用 |

## 三、原来的门禁现在怎么办

| 原来 | 现在 |
|---|---|
| `prot` 的 `verify:syntax` / `verify:api` / `verify:replay`(全是 Lua 侧) | `npm run verify` → `verify:data` → `node verify-data-js.js`(JSON ↔ JS) |
| H5 的 `prebuild` 跑 `p1-verify.js`(JSON ↔ Lua) | H5 的 `prebuild` 跑 `scripts/verify-data.mjs` → `prot/verify-data-js.js` |
| 「改了数据要按 p1-golden → p1-convert → 校验的顺序」 | 改 `prot/lua-data/*.json` 后跑 `node prot/sync-data-js.js` → `node prot/verify-data-js.js`;`prot/lua-data/*.json` → `prot/*-data.js` 是唯一需要的生成方向 |

## 四、要回看/恢复

1. 本目录内容**只读**:要看逻辑就直接读,不要改(改了也不会被任何构建用到)。
2. 万一要把 Lua 版拿回来当对照:把 `scripts/` 拷回仓库根、把 `prot/lua/` 拷回 `prot/lua/`,
   再把 `prot/p1-*.js`、`p2-replay.js`、`p0-parity.js` 拷回 `prot/`,并按 `scripts/FROZEN.md`
   里的说明恢复 `wasmoon` 依赖(`prot/paths.js` 里的 `loadWasmoon` 探测 `.lua-runner/node_modules/wasmoon`)。
3. 注意 `dump-lua-data.js`:**不要**拿它反向覆盖 `prot/lua-data/*.json` —— 它会把现役数据拉回旧版。
